# 샤프슈터 BIG 4 스캐너 V1.0

Bybit USDT 결제 무기한 선물 전체에서 네 지표의 LONG·SHORT 전환 후보를 찾는 모바일 웹 연구 도구입니다. React + TypeScript + Vite 기반이며 서버·로그인·자동매매 기능이 없습니다. **4점 점수제는 이 프로젝트의 연구 규칙이며 박문환(샤프슈터)의 공식 매매법이나 수익률 예측이 아닙니다.**

## 실행

Node.js 22 이상, npm을 사용합니다.

```sh
npm ci
npm run dev
```

화면에서 시장·시간봉·최근 봉 수·24시간 거래대금 기준을 선택하고 **검색 시작**을 누릅니다. 기본값은 코인만, 15분봉, 최근 10봉, 거래대금 1,000만 USDT(입력값 1000), 양방향, 최소 3점, TOP 5 표시입니다. 검색은 자동 실행되지 않습니다. 5·15·30·60·240분봉, 유효기간 5·10·20봉을 지원합니다.

검색 방향·최소 점수·표시 모드는 이미 계산한 결과만 필터링하므로 API를 다시 호출하지 않습니다. TOP 5는 최소 점수를 통과한 방향별 결과 최대 5개입니다. 전체 점수 보기는 최소 점수와 무관하게 성공한 모든 종목의 양방향 0~4점을 표시합니다. 동일 종목의 LONG·SHORT는 별도 행입니다. 정렬은 현재 점수 내림차순 → 마지막 유효 신호 시각 내림차순 → 종목명 오름차순입니다.

## 시장과 데이터

- V5 `instruments-info` 모든 페이지에서 `Trading`, `LinearPerpetual`, `quoteCoin=USDT`, `settleCoin=USDT`를 수집합니다.
- 코인: `symbolType=""` 또는 `innovation`, 주식: `stock`. 종목명을 보고 분류하지 않습니다.
- 전체: ETF·원자재·외환·미확인 유형도 포함합니다. 누락·알 수 없는 유형은 전체에만 포함하고 유형 미확인으로 표시합니다.
- 주식은 Bybit 개별 주식 기반 무기한 선물이며 국내외 현물 주식 전체가 아닙니다.
- ticker `turnover24h`가 기준 이상인 종목만 캔들을 요청합니다. 입력 단위는 **만 USDT**입니다.
- 종목당 한 번의 공통 OHLCV 조회(최대 1000봉)로 네 지표와 EMA50·200을 계산합니다. 확정봉 300개 미만은 데이터 부족 실패입니다.
- 검색 시작 시 Bybit 서버 시각을 고정하고 `시작 시각 + 시간봉 ≤ 서버 시각`인 봉만 사용합니다. 휴장·거래 중단 구간을 채우지 않습니다. 유효기간은 시간 경과가 아닌 실제 확정봉 개수입니다.
- `volume`과 `turnover`를 분리하며 CO에는 **volume**을 사용합니다. 중복 시각·비정상 OHLCV는 실패 처리합니다.

## 지표와 신호

지표 모듈은 `src/indicators/`에 독립적으로 구현했습니다. EMA는 최초 기간의 SMA로 초기화한 뒤 α=2/(p+1), Wilder는 최초 기간 SMA 이후 α=1/p를 사용합니다. 초기화 전 값은 null입니다.

| 지표                    | 계산                                                          | LONG                                       | SHORT                                      |
| ----------------------- | ------------------------------------------------------------- | ------------------------------------------ | ------------------------------------------ |
| DMI(14)                 | +DM/−DM/TR의 Wilder 평활화 → +DI/−DI, DX → ADX                | 이전 +DI ≤ −DI, 현재 +DI > −DI             | 이전 −DI ≤ +DI, 현재 −DI > +DI             |
| Slow Stochastic(14,3,3) | 14봉 고저 범위의 Fast K → SMA3 K → SMA3 D                     | K 상향 교차, 직전 또는 현재 K ≤ 과매도(20) | K 하향 교차, 직전 또는 현재 K ≥ 과매수(80) |
| Chaikin                 | MFM=((C−L)−(H−C))/(H−L), MFV=MFM×volume, 누적 AD의 EMA3−EMA10 | 이전 CO ≤ 0, 현재 CO > 0                   | 이전 CO ≥ 0, 현재 CO < 0                   |
| MACD                    | EMA12−EMA26, Signal EMA9, Histogram=MACD−Signal               | 이전 Histogram ≤ 0, 현재 > 0               | 이전 Histogram ≥ 0, 현재 < 0               |

ADX는 참고값이며 점수 조건이 아닙니다. CO 다이버전스나 히스토그램 단순 증감은 점수를 부여하지 않습니다. High=Low일 때 CO의 MFM은 0, 스토캐스틱의 고저 범위가 0이면 중립값 50, DMI의 TR 및 DI 합이 0이면 해당 비율을 0으로 처리합니다. 스토캐스틱 과매도·과매수는 화면에서 조정할 수 있습니다.

## 점수와 상세 보기

각 지표의 **가장 최근 신호**가 해당 방향이며 현재 봉과 신호 봉의 인덱스 차이가 N 미만일 때만 1점입니다. 반대 방향 신호는 기존 신호를 즉시 취소합니다. N=10이면 신호 발생 봉부터 9봉 뒤까지 유효하며 10봉 뒤 만료합니다. 지표당 최대 1점, 방향당 0~4점입니다.

현재 유효 점수를 필터·정렬에 사용합니다. 상세의 발생 점수 이력은 최근 N개(기본 10개) 확정봉 각각의 당시 정보만 사용한 점수이며 최고 발생 점수도 같은 구간의 최고값입니다. 미래 봉은 과거 점수 계산에 사용하지 않습니다. 신호 시각은 KST **캔들 종료 시각**으로 표시합니다.

카드에서 상세를 열면 캔들·EMA50·EMA200, 신호 위치(▲/▼, 툴팁에 지표명), 이전/다음 캔들 검사, 최신 지표값, 지표별 마지막 신호와 유효 여부, 양방향 점수 이력을 볼 수 있습니다. 차트는 최근 80개 봉을 표시합니다. 직접 연결이 검증되지 않은 TradingView 심볼은 임의 생성하지 않습니다. 현재 코인·주식 모두 직접 연결 미확인으로 표시하고, 종목 직접 검색용 TradingView 홈페이지 링크만 제공합니다.

## API 안정성과 제한

동시 종목 작업 최대 4개, 모든 요청 시도 간 최소 200ms, 타임아웃 12초, 최대 3회 시도입니다. 429·5xx·일시적 Bybit 오류·연결 오류는 지수 백오프하며 Retry-After를 존중합니다. 403이면 이후 요청도 중단하고 지역/접근 거부를 표시합니다. 실패한 종목에는 점수를 만들지 않으며 정상 0점 결과와 분리합니다. 시장 목록 실패는 전체 검색 실패, 개별 실패는 정상 결과를 유지한 부분 실패입니다. 검색 중 부분 결과와 진행률·완료·잔여·실패·3점 이상 종목 수를 표시하고 취소 후에도 완료 결과를 유지합니다.

브라우저에서 `https://api.bybit.com`에 직접 접근하므로 사용자 지역 제한·CORS·네트워크 정책·Bybit 응답 변경으로 실패할 수 있습니다. 별도 프록시나 가짜 데이터 대체는 없습니다. 데이터 지연이나 점수는 거래 적합성·수익성을 보장하지 않습니다.

## 검증

```sh
npm run typecheck
npm test
npm run build
npx playwright install --with-deps chromium
npm run preview
# 별도 터미널
npm run test:browser
# 시스템 Chromium 사용 시 CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

단위 테스트는 시장/유동성 필터, 확정봉 제외, 해석 가능한 기준 시계열의 지표값, 양방향 교차, 만료·취소·인과성, 94종목 전체 평가, 로컬 TOP 5, 실패 분리, 최대 동시성 및 API 재시도·페이지네이션을 검사합니다. 브라우저 테스트는 명시적인 합성 API fixture로 모바일 360/375px·데스크톱, 상세 차트·필터·부분 실패·전체 실패·취소를 검사하고 `test-results/`에 화면을 저장합니다. 테스트 fixture는 제품에 포함되지 않으며 실제 시장 조회 성공이나 수익성 검증을 의미하지 않습니다.

## GitHub Pages

Vite base는 `/Indicator_Dream4/`입니다. `.github/workflows/pages.yml`은 PR에서 타입 검사·단위 테스트·빌드·브라우저 테스트를 실행하고, main push에서는 검증만 실행하고, main 브랜치에서 Actions를 수동 실행(workflow_dispatch)할 때만 성공한 dist를 Pages에 배포합니다. 저장소 Settings → Pages → Source에서 **GitHub Actions**를 선택한 뒤 main에 반영하세요. 실제 배포 여부와 URL은 Actions의 deploy 결과에서 확인합니다. 로컬 빌드 성공은 원격 배포 성공을 의미하지 않습니다.
